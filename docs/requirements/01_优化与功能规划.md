## 高优先级

### 1. SetGauge 实现 Bug
**状态**: [x]
**文件**: `pkg/dataflow/metrics/recorder.go`
**描述**: `SetGauge` 内部错误调用了 `AddCounter`，导致 Gauge 指标实际行为是 Counter，无法正确反映当前值（如队列长度、连接数）。同时修复了同类型的 `ObserveSummary` 调用 `ObserveHistogram` 的 bug

### 2. 优雅关闭（Graceful Shutdown）
**状态**: [x]
**文件**: `pkg/dataflow/flow.go`, `pkg/dataflow/app/app.go`
**描述**: 当前 SIGINT 时立即停止，channel 缓冲区中的数据丢失。应支持 drain 模式：停止 source → 消费完 channel 剩余数据 → sink flush → 退出。可增加 `shutdown_timeout` 配置

### 3. 错误处理增强
**状态**: [x]
**文件**: `pkg/dataflow/flow.go`, `pkg/dataflow/app/app.go`
**描述**:
- Dead Letter Queue — processor/sink 处理失败的记录路由到 DLQ（文件或另一个 sink），而非直接中断整个 flow
- Per-record error detail — 目前只有错误计数，无法知道哪条记录、什么原因失败

### 4. Flow 错误信息丢失
**状态**: [x]
**文件**: `pkg/dataflow/flow.go`
**描述**: `flow.Run()` 只返回第一个错误，后续组件的错误被静默丢弃，应聚合所有错误后返回

## 中优先级

### 5. CLI 能力增强
**状态**: [x]
**文件**: `cmd/dataflow/main.go`, `pkg/dataflow/app/app.go`
**描述**:
- `--validate` — 只解析验证配置，不执行 flow，部署前检查
- `--env-check` — 检查所有 `${VAR}` 是否都有对应环境变量
- `--list-flows` — 列出 `-d` 目录下发现的 flow 而不执行

### 6. 常用内置 Processor
**状态**: [不做 ]
**文件**: `pkg/dataflow/builtins/processor/`
**描述**:
- Batch Processor — 按数量或时间窗口聚合后批量输出
- Dedup Processor — 按指定字段去重（滑动窗口）
- Rate Limiter — 限速控制（令牌桶/漏桶）

### 7. 常用 Source/Sink
**状态**: [ 不做]
**文件**: `pkg/dataflow/builtins/source/`, `pkg/dataflow/builtins/sink/`
**描述**:
- HTTP Source — 定时拉取 REST API
- HTTP Sink — 推送到 Webhook
- Database Source/Sink — MySQL/PostgreSQL 查询和写入

### 8. 监控增强
**状态**: [x]
**文件**: `pkg/dataflow/metrics/`, `pkg/dataflow/app/app.go`
**描述**:
- Channel 缓冲区深度 gauge（`channel_buffer_depth`）
- 吞吐量指标（records/sec）
- Health check 端点（`/health`），用于容器编排
